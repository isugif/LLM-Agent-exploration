# MDD Audit Report — 2026-08-09

Full-codebase audit (`/mdd audit`, report-only mode — no code changed). Scope: both harness
tracks (`langgraph_impl/`, `nooa_impl/`), the shared layer (`shared/`), the curator subsystem
(`curator/`), validators, and tests — ~4,200 LOC read in full.

## Executive summary

**The codebase is in good shape.** The architecture (four harnesses around a contract-driven
core, deterministic-first with narrow LLM judgment points) is consistently executed, and the
security posture is deliberate and solid:

- `safe_eval` is a restricted AST walker, not `eval` — contracts stay data, not code.
- Every tool invocation is list-argv `subprocess.run` with `shell=False`; no injection surface.
- `provision.py` whitelists managers/channels, regex-validates names, re-verifies model proposals.
- HRR markers make an unreviewed contract un-routable by construction.
- Graceful LLM degradation is uniform across both tracks.
- Tests: **14 pass / 0 fail / 1 skip** (LLM-dependent case), both tracks, deterministic mode.

**15 findings**: 2 High, 4 Medium, 1 Modularity (the headline), 8 Low. Nothing exploitable or
data-corrupting; the Highs are a hang risk and a silently-wrong provider preference.

Note: the working tree carried uncommitted WIP during this audit (multiqc clean sections,
`bio-tools/seqkit/`); it was read but not touched.

## Findings

### HIGH

#### 1. Missing subprocess timeouts in source acquisition
`curator/references/sourcing.py:44-58` (`source_from_help`) and `:66` (`version_from_tool`) are
the **only** `subprocess.run` calls in the repo without `timeout=`. A tool whose `--help` opens a
pager or waits on input hangs the whole curation pipeline indefinitely. Every other call site
(runner, provision, CLI providers) sets one.
**Fix:** add `timeout=` (~30 s) + `except TimeoutExpired` → empty chunk. Est: 5 min.

#### 2. Provider role-name mismatch: `"transfer"` vs `"source_transfer"`
`curator/providers/registry.py:25` defines `ROLE_PREFERENCE["source_transfer"] = ["claude-cli",
"codex-cli", "ollama"]`, but every caller resolves role `"transfer"` (`run_m32.py:33`,
`run_provision_demo.py:24`, `references_demo.py:35,45`; only `smoke_m31.py:46` uses the right
key). `resolve("transfer")` silently falls to the default `["ollama"]`, so the intended
claude-first precision path for source transfer **never applies** unless overridden. Currently
masked because all drivers pass `override="ollama"` — it will bite the first time a driver runs
without an override.
**Fix:** rename the key (or the role string) so they match. Est: 2 min.

### MEDIUM

#### 3. 8,000-char source truncation vs flag-grounding validators
`sourcing.py:source_from_help` truncates concatenated help text to 8,000 chars (`[:8000]`);
`curator/validators/framework.py:usage_flags_grounded` / `options_flags_grounded` then flag any
flag absent from that truncated text as `UNGROUNDED_FLAG`. Long-help tools (hisat2, seqkit
subcommands — both on the expansion path) will get spurious validation failures, or curation from
an incomplete source. The two limits were chosen independently and interact badly.
**Fix:** ground against the untruncated text (thread it separately in ctx), or raise the cap and
make it one named constant. Est: 20 min.

#### 4. `safe_eval` missing-fact semantics contradict the documented contract
`shared/contracts_lib.py:205-209`: attribute access on a missing fact returns `None` (dict
`.get`). Consequence: `measured.format == 'fastq'` with `format` absent evaluates cleanly to
`False` → **blocking refusal**, while `measured.n_reads > 0` with `n_reads` absent raises
TypeError → **warning** ("uncheckable"). The `evaluate_preconditions` docstring (`:229-230`)
promises the warning path for un-checkable assumptions; equality/membership asserts silently take
the block path instead. Also `:190-192`: `BoolOp` evaluates **all** operands (no short-circuit),
so an author can't guard a comparison behind an existence check.
**Fix:** raise `KeyError` on missing namespace keys so every missing fact uniformly becomes an
uncheckable warning; short-circuit `and`/`or`. Est: 30 min incl. test cases.

#### 5. NOOA `BoundaryCheck` prompt hardcodes "FastQC"
`nooa_impl/agents/judgment.py:19`: the `violates` field description reads "True only if FastQC
itself is asked to do the forbidden thing" — but `JudgmentAgent` is tool-generic and already
judges multiqc. The LangGraph twin (`langgraph_impl/harnesses/judgment.py:23`) says "the tool".
Cross-track prompt divergence for every non-fastqc tool, on the exact step the comparison
measures. Est: 2 min.

#### 6. `provision.py` unguarded environment assumptions
`ensure_env()` (`curator/stages/provision.py:62-64`) ignores the returncode of `mamba create`;
`_conda_base()` (`:52-55`) doesn't handle conda being absent. If mamba/conda is missing or env
creation fails, `ensure_installed` raises `FileNotFoundError` (or proceeds against a nonexistent
env) instead of returning `InstallOutcome(installed=False, reason=…)` — breaking the module's own
"never crash, gate cleanly" contract. Est: 20 min.

### MODULARITY — the headline recommendation

#### 7. Four-harness logic duplicated across tracks; drift already visible
The step logic is written twice — once per track — and has begun to diverge:

| Logic | LangGraph copy | NOOA copy | Drift? |
|---|---|---|---|
| reconcile declared/measured | `harnesses/onboarding.py:24` `_reconcile` | `agents/onboarding.py:33` `reconcile` | **Yes** — NOOA None-guards (`(x or "unknown")`), LangGraph doesn't |
| route composition | `harnesses/judgment.py:85-101` | `agents/judgment.py:52` `route` | identical today |
| crash diagnosis | `harnesses/diagnosis.py` | `agents/diagnosis.py` | identical today |
| metric scoring loop | `harnesses/evaluation.py:36-43` | `agents/evaluation.py:37` `score` | identical today |

The curator already solved exactly this problem: `curator/stages/steps.py` holds pure stage
functions and the two orchestrations only *wire* them — which is also what keeps the framework
comparison honest (same behavior, different idiom). The harness tracks predate that pattern.
BACKLOG's "Proactive parity / consistency gates" item polices this drift reactively; extracting
the steps prevents it.

**Paste-ready BACKLOG.md item:**

```markdown

**Status:** 📋 scoped (from the 2026-08-09 audit)

**Why it matters:** the copies have already drifted (NOOA's reconcile None-guards, LangGraph's

**Est:** 2-3 h, own branch (`refactor/shared-harness-steps`). Verify: `python tests/run_tests.py`
unchanged 14/14; diff both tracks' reports on identical inputs.
```

### LOW — efficiency & hygiene

8. **`get_provider()` re-pings Ollama per node** — 3× `GET /api/tags` (3 s timeout each) per
   LangGraph run (`onboarding.py:40`, `judgment.py:58`, `evaluation.py:49`); the provider can
   also flip mid-run, making the reported `llm_provider` stale. Resolve once and carry it in
   state, or memoize.
9. **`cl.load_contract()` re-reads yml 4-5× per run** (every node; every NOOA agent `__init__`).
   Trivial cost today; `functools.lru_cache` returning a deep copy removes it.
10. **`fastq_probe.py:64-67`** — per-char `ord()` loop (~1.5 M calls at the 10 k-read default);
    byte-level `min`/`max` is ~10× faster. Also `rstrip("\n")` leaves `\r` on CRLF FASTQ, and
    `\r` (13) forces `encoding_guess` to "unknown" — use `rstrip("\r\n")`.
11. **Triplicated `OLLAMA_HOST`/`OLLAMA_MODEL` constants** (`shared/llm/provider.py`,
    `nooa_impl/llm.py`, `curator/providers/ollama.py`) — one shared config point would do.
12. **`curator/run_m32.py:20-21`** — duplicated `sys.path.insert` line; docstring still says
    `python temp/curator/run_m32.py` (file lives at `curator/run_m32.py`).
13. **Orphaned `app/__pycache__`** — `app/` holds only stale bytecode (`app/api`,
    `app/capabilities`, `app/tests` contain nothing but `.pyc`; source was deleted). Gitignored
    and harmless, but confusing. Recommend `rm -rf app` — left for you to confirm.
14. **`requirements.txt` fully unpinned.** For a repo whose *conclusions* compare framework
    behavior, pin at least `langgraph`/`langchain-core` (and `pydantic` major) so results stay
    reproducible.
15. **Temp-dir accumulation** — `tests/run_tests.py:_build_multiqc_input` and every pipeline run
    (`tempfile.mkdtemp`) leave dirs in `$TMPDIR`. Deliberate for report persistence in runs, but
    the test harness could clean up after `REPORT.md` is written.
